# SUEZ Enhanced v0.7.0 — implementation plan

This is an incremental development branch, **not a release**. Keep v0.6.3 on `main` until Home Assistant testing passes.

## Implemented in first commit
- In-memory daily API response cache: after the latest eligible day (today minus two days) has a volume, six-hour coordinator refreshes reuse the cached 35-day response for the remainder of the local day.
- When the latest eligible day is absent, polling retries normally.
- A restart clears the cache; this is deliberate and must not be mistaken for a durable API cache.

## Implemented in second commit
- Skip the SUEZ API connection entirely during cache-only refreshes, except when a historical gap requires a backfill fetch.
- Merge Recorder and recent API readings by date, preferring fresh API readings while retaining historical values when an API response omits a day.

## Implemented in third increment
- Versioned Home Assistant Store cache, scoped to the configuration entry, meter ID and local date. A restart can reuse complete daily telemetry without an API request.
- Validate cached dates and numeric values; corrupt or unreadable cache falls back to the API.
- Persist successful telemetry downloads; storage errors do not prevent sensor refresh.

## Implemented in fourth increment
- Forward gap recovery now runs in a background task after entity setup instead of downloading up to a year of windows during initial coordinator refresh.
- At most 14 days are fetched per pass, with a five-minute pause between batches. The last committed Recorder day is the restart checkpoint.
- The task stops when data is missing or on error, and is cancelled on integration unload. Recorder append-only semantics remain unchanged.
- This is **forward gap recovery only**, not yet a full multi-year discovery/import of older history.

## Implemented in fifth increment
- Read-only yearly consumption and estimated cost summaries from up to 20 calendar years of existing Recorder statistics, cached once per local day.
- New `Recorded annual consumption` sensor exposes a compact `years` mapping (liters, m³, estimated EUR, day count and completeness). It does not publish thousands of daily points as attributes.
- Existing YTD and ApexCharts daily/cumulative attributes remain unchanged. Historical years are **not yet imported** from the API.

## Implemented in sixth increment
- Added an **opt-in, disabled-by-default** older-history API scanner (`older_history_import_enabled`).
- Scanner anchors at the earliest Recorder day found in the last five years, then scans backward in 14-day windows, with five minutes between requests and a maximum five-year horizon.
- Stores older readings in a separate versioned Home Assistant Store archive; **never prepends to the legacy Recorder statistic**, which would risk corrupting cumulative sums.
- Checkpoint is persisted after each successful window, including empty API responses. Four consecutive empty windows stop scanning without claiming the API has no older data.
- Scanned archive is included in read-only annual summaries as of the seventh increment; integration tests remain outstanding.

## Implemented in seventh increment
- Read-only yearly summaries now combine the isolated older-history archive with Recorder, giving Recorder priority for overlapping days.
- Annual attributes distinguish `recorder_days` and `archive_only_days`, and continue marking incomplete years.
- Archive cursor changes invalidate the annual summary cache without requiring a new calendar day.
- No archived readings are written into the existing cumulative Recorder series.

## Implemented in eighth increment
- Fixed backward scan anchoring: inspect all candidate Recorder years and select the **earliest** recorded day rather than the first year encountered in ascending order.
- Persist the count of consecutive empty API windows in the archive checkpoint; restarts no longer reset the four-empty-window safety limit.
- Existing archives lacking this field default to zero for backward compatibility.

## Implemented in ninth increment
- Added standalone Python unittest regressions for consecutive-day selection, missing days, identical/conflicting duplicates, invalid values, meter-index deltas, Paris DST transitions, leap-year completeness and annual cost calculations.
- These tests do not require Home Assistant to be running. **They have been committed but not executed in this session**; the environment cannot reach the GitHub repository for a checkout.
- Home Assistant integration tests, API response mocks and live installation validation remain outstanding.

## Implemented in tenth increment
- Added mocked Home Assistant Store tests for restart persistence, consecutive empty windows, archive conflicts and strict 14-day window bounds.
- Added GitHub Actions workflow to compile Python files and run the standalone unittest suite on Python 3.13 and 3.14 for pushes and pull requests.
- Local checkout was unavailable in this session; **the new CI workflow has been committed but its run result has not been inspected or confirmed**. Do not interpret test code being present as tests passing.

## Remaining work before v0.7.0
1. Add a bounded periodic correction-check policy to the persistent daily cache; date and meter invalidation are implemented.
2. Validate bounded older-history discovery against actual SUEZ responses; scanning is implemented but currently opt-in and capped at five years.
3. Test the archive/Recorder merge and add controlled retry scheduling for missing days.
4. Preserve legacy Recorder statistic ID and units; append only contiguous days. Add explicit handling for missing internal days and separate, opt-in retroactive correction reconciliation with an audit log.
5. Validate compact multi-year comparisons on Home Assistant and provide example dashboard charts; annual summary now includes archived older years.
6. Add diagnostics: oldest known day, latest imported day, missing days, backfill status, API cache status, last error and correction status.
7. Execute the new standalone tests and add mocked Home Assistant/Recorder and SUEZ API tests for rate limits, restart mid-backfill, recorder gaps and API corrections.
8. Validate on the user's HA instance before merging or tagging v0.7.0.

## Known caveats
- Current in-memory cache uses the latest *eligible* day, not necessarily yesterday; this matches the existing two-day import safety rule.
- Cache-only coordinator updates no longer establish an API connection unless a gap backfill requires it.
- Cache is now persisted through Home Assistant Store and reloaded after restart when its date and meter match.
- Existing 35-day current telemetry fetch remains; long forward gaps are recovered in bounded background batches. Older history scanning exists but remains disabled by default and untested on live SUEZ.
