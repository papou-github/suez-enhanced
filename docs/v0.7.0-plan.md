# SUEZ Enhanced v0.7.0 — implementation plan

This is an incremental development branch, **not a release**. Keep v0.6.3 on `main` until Home Assistant testing passes.

## Implemented in first commit
- In-memory daily API response cache: after the latest eligible day (today minus two days) has a volume, six-hour coordinator refreshes reuse the cached 35-day response for the remainder of the local day.
- When the latest eligible day is absent, polling retries normally.
- A restart clears the cache; this is deliberate and must not be mistaken for a durable API cache.

## Implemented in second commit
- Skip the SUEZ API connection entirely during cache-only refreshes, except when a historical gap requires a backfill fetch.
- Merge Recorder and recent API readings by date, preferring fresh API readings while retaining historical values when an API response omits a day.

## Implemented in third increment
- Versioned Home Assistant Store cache, scoped to the configuration entry, meter ID and local date. A restart can reuse complete daily telemetry without an API request.
- Validate cached dates and numeric values; corrupt or unreadable cache falls back to the API.
- Persist successful telemetry downloads; storage errors do not prevent sensor refresh.

## Implemented in fourth increment
- Forward gap recovery now runs in a background task after entity setup instead of downloading up to a year of windows during initial coordinator refresh.
- At most 14 days are fetched per pass, with a five-minute pause between batches. The last committed Recorder day is the restart checkpoint.
- The task stops when data is missing or on error, and is cancelled on integration unload. Recorder append-only semantics remain unchanged.
- This is **forward gap recovery only**, not yet a full multi-year discovery/import of older history.

## Implemented in fifth increment
- Read-only yearly consumption and estimated cost summaries from up to 20 calendar years of existing Recorder statistics, cached once per local day.
- New `Recorded annual consumption` sensor exposes a compact `years` mapping (liters, m³, estimated EUR, day count and completeness). It does not publish thousands of daily points as attributes.
- Existing YTD and ApexCharts daily/cumulative attributes remain unchanged. Historical years are **not yet imported** from the API.

## Remaining work before v0.7.0
1. Add a bounded periodic correction-check policy to the persistent daily cache; date and meter invalidation are implemented.
2. Discover the earliest API date with bounded, rate-limited requests; distinguish empty valid responses from timeouts and errors. Do not infer that the API provides all earlier years.
3. Extend the background worker with safe older-than-existing-history discovery/import; the current forward-only worker checkpoints in Recorder, but cannot prepend older dates. Add controlled retry scheduling for missing days.
4. Preserve legacy Recorder statistic ID and units; append only contiguous days. Add explicit handling for missing internal days and separate, opt-in retroactive correction reconciliation with an audit log.
5. Extend the compact multi-year summaries into tested charts/comparisons; the read-only annual summary sensor is implemented, while existing YTD attributes remain unchanged.
6. Add diagnostics: oldest known day, latest imported day, missing days, backfill status, API cache status, last error and correction status.
7. Test DST boundaries, year changes, missing days, rate limits, restart mid-backfill, recorder gaps and API corrections against mocked Home Assistant and SUEZ responses.
8. Validate on the user's HA instance before merging or tagging v0.7.0.

## Known caveats
- Current in-memory cache uses the latest *eligible* day, not necessarily yesterday; this matches the existing two-day import safety rule.
- Cache-only coordinator updates no longer establish an API connection unless a gap backfill requires it.
- Cache is now persisted through Home Assistant Store and reloaded after restart when its date and meter match.
- Existing 35-day current telemetry fetch remains; long forward gaps are now recovered in bounded background batches. Older historical discovery/import is not implemented yet.
